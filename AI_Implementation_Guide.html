Step 1 — Choose Your Model

Recommended: Ollama + qwen2.5:7b

Your code already has the OllamaPlanningModel class written and ready in fine_tuned.py. You just need to install Ollama and pull the model.

Why qwen2.5:7b?

  • Best-in-class at JSON structured output (your primary need)
  • Supports Ollama's native format parameter (forces strict JSON schema compliance)
  • Runs on Mac M-chip or any 16 GB RAM machine
  • Free, fully offline, no API keys required
  • Already hardcoded as the default in your OllamaPlanningModel

Alternative models:

Step 3a — Create Training Dataset

You need 100–200 examples in this format:

[
  {
    "instruction": "You are DataPilot AI. Convert the user requirement to a JSON workflow spec.",
    "input": "Find 50 Indian SaaS startups with founder names, website, and funding stage",
    "output": "{\"intent\": \"extract_companies\", \"entity_type\": \"company\", \"target_count\": 50, \"filters\": {\"country\": \"India\", \"industry\": \"SaaS\"}, \"fields\": [\"company_name\", \"founder\", \"website\", \"funding_stage\"]}"
  },
  {
    "instruction": "You are DataPilot AI. Convert the user requirement to a JSON workflow spec.",
    "input": "Get backend jobs in Bangalore",
    "output": "{\"intent\": \"extract_jobs\", \"entity_type\": \"job\", \"filters\": {\"role\": \"backend\", \"city\": \"Bangalore\"}}"
  }
]

You can generate this dataset automatically using MockRuleBasedModel — run 200 diverse prompts through it and save the input/output pairs as your training data.

Step 3b — Google Colab Fine-Tuning Script

# Run this in Google Colab (free T4)
!pip install unsloth

from unsloth import FastLanguageModel
import torch

model, tokenizer = FastLanguageModel.from_pretrained(
    model_name="unsloth/Qwen2.5-7B-Instruct",
    max_seq_length=2048,
    load_in_4bit=True,  # Fits in T4 16 GB
)

model = FastLanguageModel.get_peft_model(
    model,
    r=16,
    target_modules=["q_proj", "k_proj", "v_proj", "o_proj"],
    lora_alpha=16,
    lora_dropout=0,
    bias="none",
    use_gradient_checkpointing=True,
)

# After training:
model.save_pretrained_gguf("datapilot-model", tokenizer, quantization_method="q4_k_m")
# Upload GGUF to Hugging Face, then run:
# ollama create datapilot from datapilot-model.gguf

Step 4 — Scraping Strategy

Your pipeline already has 3 scrapers. Here is how to enable them properly.

Priority 1: Tavily Search API (Already Working)

  • You already have TAVILY_API_KEY in your .env
  • Returns search snippets and URLs for any query
  • Used in ai/app/tools/tavily.py
  • Limitation: Only returns snippets, not full page content

Priority 2: Firecrawl API (Needs API Key)

Firecrawl scrapes full page content and returns clean Markdown. Add your key:

FIRECRAWL_API_KEY=fc-your-key-here

Get a free key at firecrawl.dev — 500 credits included.

Priority 3: Crawl4AI (100% Free, Open Source)

If you don't want to pay for Firecrawl, use Crawl4AI — it is better and completely free:

# In your ai/ folder
pip install crawl4ai
crawl4ai-setup  # installs Playwright browser
# ai/app/tools/crawl4ai_scraper.py
from crawl4ai import AsyncWebCrawler
from crawl4ai.extraction_strategy import LLMExtractionStrategy

async def scrape_with_crawl4ai(url: str, schema: dict) -> list[dict]:
    async with AsyncWebCrawler(verbose=False) as crawler:
        result = await crawler.arun(
            url=url,
            extraction_strategy=LLMExtractionStrategy(
                provider="ollama/qwen2.5:7b",  # Uses your local model, no API cost
                api_token="no-key-needed",
                schema=schema,
                instruction="Extract all company/job records from this page as JSON array"
            ),
            bypass_cache=False,
        )
        return result.extracted_content

Why Crawl4AI is the best option:

  • Uses your local Ollama model — zero API cost
  • Handles JavaScript-rendered pages
  • Extracts structured JSON directly from any page

Recommended Scraper Stack

1. Tavily      ->  Finds relevant URLs            (already works)
2. Crawl4AI    ->  Scrapes full page content      (free, use local Ollama)
3. Semantic    ->  Validates and cleans fields    (uses same Ollama model)

Step 5 — General / Conversational Responses

Your OllamaPlanningModel system prompt already instructs the model:

"Greetings are entity_type conversation, intent conversation, target_count 0, with a friendly plan_summary."

So when a user says "Hello" or "What can you do?", the model returns:

{
  "entity_type": "conversation",
  "intent": "conversation",
  "target_count": 0,
  "plan_summary": "Hi! I am DataPilot. Describe what data you need and I will collect it for you."
}

The workflow in ai/app/graph/workflow.py already routes entity_type: "conversation" to END. You just need to handle it in your backend worker — when AI returns a conversation spec, save plan_summary as the chat reply to the user instead of starting a data collection job.
